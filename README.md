
# Selenium Java Hybrid Automation Framework

A UI test automation framework built using Selenium WebDriver, Java, Cucumber BDD, TestNG, Maven and the Page Object Model (POM).

The framework automates end-to-end user workflows on the SauceDemo web application, including Login, Shopping Cart and Checkout functionality.

## 1. Technology Stack

| Technology | Purpose |
|------------|---------|
| Java 21 | Programming language |
| Selenium WebDriver 4.27.0 | Browser automation |
| Cucumber BDD 7.20.1 | Behavior-driven test scenarios |
| TestNG 7.10.2 | Test execution and assertions |
| Maven | Dependency and build management |
| Page Object Model | Test automation design pattern |
| XPath | Web element identification |
| Git & GitHub | Version control |
| Cucumber Reports | HTML, JSON and XML reporting |

## 2. Framework Features

- Page Object Model (POM) architecture
- Separate XPath locator classes
- Cucumber BDD feature files
- TestNG assertions
- Maven-based execution
- Reusable WebDriver management
- ThreadLocal WebDriver implementation
- Explicit waits for element synchronization
- Positive and negative test scenarios
- Scenario Outline with Examples
- Smoke and regression test tagging
- Screenshot capture after every Cucumber step
- Screenshots embedded directly in Cucumber HTML reports
- Additional screenshots for failed scenarios
- Automatic browser initialization and cleanup

## 4. Framework Architecture

The framework follows a layered automation architecture.

```text
Cucumber Feature Files
          |
          v
Step Definition Classes
          |
          v
Page Object Classes
          |
          v
XPath Locator Classes
          |
          v
Selenium WebDriver
          |
          v
SauceDemo Application
```

### Feature Files

Contain business-readable test scenarios written in Gherkin syntax.

### Step Definitions

Map Gherkin steps to Java methods.

Responsibilities include:
- Calling Page Object methods
- Performing TestNG assertions
- Attaching screenshots to Cucumber scenarios

### Page Object Classes

Contain Selenium interaction logic, explicit waits and page-level validations.

### Locator Classes

Contain XPath locators used by the corresponding Page Object classes.

### Utility Classes

Provide reusable functionality such as WebDriver lifecycle management and screenshot capture.

## 9. Execute Automation Tests

Run all scenarios using Maven:

```bash
mvn clean test
```

If automatic ChromeDriver management is unavailable, provide the path to a compatible ChromeDriver executable.

Example for Windows PowerShell:

```powershell
mvn clean test "-Dwebdriver.chrome.driver=C:\path\to\chromedriver.exe"
```

The framework currently executes tests using Google Chrome.

The framework generates Cucumber reports in the following formats:

| Report | Location |
|--------|----------|
| HTML | reports/cucumber.html |
| JSON | reports/cucumber.json |
| XML | reports/cucumber.xml |

After test execution, open:

```text

```

The HTML report provides:

- Feature-wise execution results
- Scenario-wise execution status
- Individual Gherkin steps
- Screenshots attached after each step
- Failure evidence when available

Generated reports are excluded from Git version control through `.gitignore`.

## 11. Screenshot Implementation

Screenshots are captured using Selenium's TakesScreenshot interface.

The framework attaches screenshots to Cucumber scenarios using:

```java
scenario.attach(
    screenshot,
    "image/png",
    screenshotName
);
```

Screenshot capture is implemented in the Step Definition classes.

For assertion steps, screenshot capture is placed inside finally blocks to preserve evidence when assertions fail.

The Cucumber After hook also captures an additional screenshot when a scenario fails.

## 12. Cucumber Tags

The framework uses tags to classify test scenarios.

| Tag | Purpose |
|-----|---------|
| @smoke | Critical functionality |
| @regression | Regression coverage |
| @positive | Positive test scenarios |
| @negative | Negative test scenarios |
| @cart | Shopping cart functionality |
| @checkout | Checkout functionality |

Tags are defined in the feature files.
